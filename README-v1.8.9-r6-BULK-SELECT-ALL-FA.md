# راهنمای کاندیدای v1.8.9-r6 — ثبت Excel و انتخاب همه در فرم دستی

وضعیت: **DEV / QA ONLY**. مشتق مستقیم از بستهٔ کامل `v1.8.9-r5`، بدون تغییر DB Schema، Migration، Docker Compose، Environment، RBAC، لاگین یا منطق ثبت سمت سرور. این بسته خودکار هیچ تغییری روی سرور اصلی ایجاد نمی‌کند.

## تفاوت دو فرم روی صفحه

صفحهٔ `/managers/attendance/bulk` **دو فرم مستقل** دارد:

1. **«ورود گروهی با فایل Excel»**: یک فایل `.xlsx` با حداکثر ۱۰۰۰ سطر/۲ مگابایت را انتخاب کنید و دکمهٔ «اعتبارسنجی و ثبت مستقیم Excel» را بزنید. برای مثال، فایل آزمایشی ۵ مدیر × ۳۰ روز = **۱۵۰ سطر** در یک نوبت بررسی و اتمیک ذخیره می‌شود. هیچ تیکی در جدول پایین لازم نیست. در حساب ادمین، رکوردهای معتبر بلافاصله در گزارش‌ها اثر می‌گذارند؛ در حساب قدیمی منشی، به صف می‌روند. اگر یک سطر اشتباه، تکراری یا متداخل باشد، **هیچ‌کدام** از سطرهای همان فایل ذخیره نمی‌شوند. انتخاب فایل، به‌تنهایی بارگذاری و ثبت نیست؛ باید دکمهٔ مخصوص همین فرم زده شود.
2. **«ثبت دستی یک روز برای چند مدیر»**: برای هر مدیرِ انتخاب‌شده تاریخ شمسی، ساعت ورود، ساعت خروج و دلیل واقعی لازم است. نوشتهٔ خاکستریِ `08:00`، `17:00` و «براساس اعلام مدیر» فقط **placeholder** است و به‌عنوان مقدار ارسال نمی‌شود.

## امکانات رابط جدید r6

- سرستون «انتخاب همه» همهٔ مدیران **نمایش‌داده‌شده** در فرم دستی را علامت می‌زند؛ با برداشتن آن همه لغو می‌شوند. در انتخاب جزئی، وضعیت نیمه‌انتخاب دیده می‌شود.
- محدودیت سرور همان **۲۵ مدیر در یک نوبت دستی** است. اگر نتایج جستجو بیشتر از ۲۵ باشد، «انتخاب همه» غیرفعال و راهنمای محدودکردن با جستجو نمایش داده می‌شود. محدودیت ۲۵ به Excel مربوط نیست.
- برای تکرار یک ساعت یا دلیل روی چند مدیر می‌توان یک‌بار در قسمت «مقادیر مشترک» نوشت و «اعمال روی انتخاب‌شده‌ها» را زد؛ مقادیر فقط به ردیف‌های تیک‌خورده و فقط با اقدام صریح کاربر کپی می‌شوند. مقادیر خالی، فیلد ردیف را تغییر نمی‌دهند.
- شمارندهٔ انتخاب‌ها و پیام خطای قابل مشاهده (`aria-live`) در فرم دستی وجود دارد.
- پیش از ارسال فرم دستی، نبود انتخاب، بیشتر از ۲۵ مورد، ساعت خالی/نامعتبر، خروج قبل از ورود و دلیل کوتاه‌تر از ۵ نویسه در مرورگر تشخیص داده می‌شود؛ فرم ارسال نمی‌شود و روی فیلد مشکل‌دار تمرکز می‌کند. **تمام کنترل‌های قبلی سمت سرور همچنان فعال‌اند** و خطای تداخل پایگاه داده می‌تواند پس از ارسال نیز رخ دهد.
- JavaScript به‌صورت داخلی با همان nonce سیاست امنیت محتوا (CSP) اضافه شده؛ بدون CDN و بدون تغییر تنظیمات امنیتی.

## بازبینی اینکه Excel واقعاً ثبت شده است

در دیتابیس **ساختگی QA** (نه دیتابیس اصلی)، نتیجهٔ ثبت مستقیم ادمین را با خواندن تعداد اصلاح‌ها بررسی کنید:

```bash
docker exec "$QA_R4_DB" psql -U attendanceqa -d attendanceqa \
  -c "SELECT origin, COUNT(*) FROM attendance_corrections GROUP BY origin ORDER BY origin;"
```

نکته: همهٔ رکوردهای `manager_manual` ممکن است شامل ثبت تکی، گروهی دستی و Excel باشند؛ برای تفکیک دقیق ۱۵۰ ردیف از تاریخ، کد مدیر، زمان عملیات و `audit_logs` کمک بگیرید. اگر قبلاً فایل ثبت شده باشد، تلاش دوباره برای همان مدیر/روز عمداً با خطای تداخل رد می‌شود.

## آزمون‌های بدون اتصال به Production

پس از استخراج ZIP در مسیر موقت، در ریشهٔ پروژه:

```bash
python3 scripts/check_project.py .
python3 -m compileall -q app tests
node tests/test_manager_bulk_select_all.cjs
```

تست Node.js فقط به Node.js استاندارد نیاز دارد و انتخاب همه، عدم قبول placeholder، تکثیر دلیل مشترک و سقف ۲۵ مدیر را با همان کد JS درون `app/main.py` بررسی می‌کند. اگر Node روی سرور نصب نیست، این تست اختیاری است.

برای تست FastAPI/SQLite با Image از پیش‌موجود در محیط ایزوله:

```bash
docker run --rm --network none --read-only --cap-drop ALL \
  --security-opt no-new-privileges --user 10001:10001 \
  --memory 512m --pids-limit 64 \
  --tmpfs /tmp:rw,noexec,nosuid,size=32m \
  --workdir /qa/app \
  -e PYTHONDONTWRITEBYTECODE=1 -e PYTHONPATH=/qa/app \
  -e DATABASE_URL='sqlite+pysqlite:///:memory:' \
  -e SESSION_SECRET='synthetic-r6-tests-only' \
  -v "$PWD/app:/qa/app:ro" -v "$PWD/tests:/qa/tests:ro" \
  --entrypoint python "$ATTENDANCE_QA_IMAGE" \
  -m unittest discover -s /qa/tests -p 'test_admin_direct_attendance.py' -v
```

همچنین مجموعه‌های `test_managers_manual_attendance.py` و `test_manager_excel_parser.py` باید PASS شوند. قبل از انتشار نهایی، تست مرورگریِ واقعی روی QA، اثبات ثبت ۱۵۰ سطر، و بررسی Backup/Restore و Release Gate الزامی است. **نباید** دیتابیس یا کانتینر Production را برای آزمون این بسته متوقف، بازنویسی یا پاک کرد.
