# راهنمای نسخهٔ آزمایشی v1.8.9-r7 — پیش‌نمایش و انتخاب ردیف‌های Excel

**وضعیت: DEV/QA؛ آمادهٔ انتشار Production نیست.** این بستهٔ کامل از `r6` مشتق شده و ساختار DB، مایگریشن، Compose، مدل‌های کاربر، نقش‌ها و ثبت خام دستگاه را تغییر نمی‌دهد.

## گردش کار جدید

در مسیر `/managers/attendance/bulk` دو فرم مجزا وجود دارد:

1. **Excel:** یک فایل `.xlsx` معتبر (حداکثر ۲ مگابایت و ۱۰۰۰ ردیف) بارگذاری کنید و روی «بررسی فایل و نمایش پیش‌نمایش Excel» بزنید. هنوز هیچ رکوردی وارد دیتابیس نمی‌شود.
2. **پیش‌نمایش:** همهٔ ردیف‌های فایل (مثلاً **۱۵۰ ردیف**) در جدول مستقلی با ارتفاع **۵۲۰px**، اسکرول عمودی داخلی، هدر ثابت و ستون‌های کد/نام مدیر، روز شمسی، ورود، خروج، دلیل و وضعیت نمایش داده می‌شوند. روی صفحه‌های باریک، جدول به‌صورت افقی در محدودهٔ خود اسکرول می‌شود؛ نه کل صفحه.
3. **انتخاب:** بالای جدول «انتخاب همهٔ ردیف‌های قابل ثبت» و شمارندهٔ انتخاب‌ها قرار دارد. می‌توان همه یا فقط بخشی از ردیف‌ها را تیک زد. ردیف‌های قبلاً ثبت‌شده یا دارای تداخل با دستگاه/اصلاح/درخواست pending، مشخص و **غیرفعال** می‌شوند. Select All فقط موارد مجاز را انتخاب می‌کند.
4. **ثبت نهایی:** فقط با زدن دکمهٔ تأیید نهایی، ردیف‌های انتخابی مجدداً در سرور اعتبارسنجی می‌شوند. در حساب `admin`، همهٔ انتخاب‌های معتبر در **یک تراکنش** به `attendance_corrections` اضافه می‌شوند؛ در حساب `secretary` به صف قدیمی تأیید می‌روند. اگر حتی یک ردیف انتخابی در فاصلهٔ پیش‌نمایش و تأیید متداخل شود، **هیچ‌کدام** از انتخاب‌ها ثبت نمی‌شود.

فرم قدیمی «ثبت دستی یک روز برای چند مدیر» و سقف آن (**۲۵ مدیر**) تغییری نکرده‌اند. سقف Excel همچنان ۱۰۰۰ ردیف است و به انتخاب دستی مربوط نیست.

## امنیت پیش‌نمایش

- هیچ فایل آپلودی روی دیسک، داخل Session Cookie یا دیتابیس موقت ذخیره نمی‌شود.
- داده‌های پارس‌شده در توکن **امضاشده و فشرده** توسط `itsdangerous` قرار می‌گیرند. توکن با `SESSION_SECRET`، شناسهٔ کاربر، امضای نشست و CSRF گره می‌خورد و **۲۰ دقیقه** اعتبار دارد. توکن رمزنگاری‌شده نیست؛ صرفاً صحت و مالکیت آن احراز می‌شود.
- شمارهٔ ردیف‌های انتخابی از سمت مرورگر به‌تنهایی مورد اعتماد نیست؛ تمام انتخاب‌ها باید عضو دادهٔ امضاشده باشند.
- هر بار در مرحلهٔ ثبت، شرایط مدیر، زمان، علت، وجود پانچ دستگاه، تداخل اصلاح و درخواست pending از ابتدا بررسی می‌شود. قفل مدیرها ترتیب پایدار و همان رفتار اتمیک r6 را حفظ می‌کند.
- CSP دارای nonce، RBAC، CSRF و Audit باقی مانده‌اند. هیچ API قدیمی برای دورزدن مرحلهٔ پیش‌نمایش جهت ثبت مستقیم Excel باقی نمانده است.

## وضعیت دیتابیس آزمایشی قبلی

در QA نسخهٔ `r6`، پنج مدیر اولیه از فایل Excel هرکدام ۳۰ رکورد و مدیر ششم یک رکورد دستی دارند (مجموعاً ۱۵۱ رکورد). اگر **همان فایل** ۱۵۰ ردیفی مجدداً در r7 پیش‌نمایش شود، هر ۱۵۰ ردیف نمایش داده می‌شوند اما وضعیت «قبلاً ثبت یا اصلاح شده» می‌گیرند و برای ثبت مجدد قابل انتخاب نخواهند بود. این رفتار عمدی است، زیرا نباید دادهٔ واقعی یا آزمایشی قبلی تکرار شود. برای آزمایش ثبت ۱۵۰ ردیف تازه، باید از **دیتابیس ساختگی خالی دیگری** یا فایل با تاریخ‌های آزاد و مجاز استفاده کرد.

## آزمون‌های ایزوله

```bash
python3 scripts/check_project.py .
python3 -m compileall -q app tests
node tests/test_manager_excel_preview.cjs
node tests/test_manager_bulk_select_all.cjs
```

در محیطی که Image دارای وابستگی‌های FastAPI و SQLite است، مانند QA موجود:

```bash
docker run --rm --network none --read-only --cap-drop ALL \
  --security-opt no-new-privileges --user 10001:10001 \
  --memory 512m --pids-limit 64 \
  --tmpfs /tmp:rw,noexec,nosuid,size=32m \
  --workdir /qa/app \
  -e PYTHONDONTWRITEBYTECODE=1 -e PYTHONPATH=/qa/app \
  -e DATABASE_URL='sqlite+pysqlite:///:memory:' \
  -e SESSION_SECRET='synthetic-r7-tests-only' \
  -v "$PWD/app:/qa/app:ro" -v "$PWD/tests:/qa/tests:ro" \
  --entrypoint python "$ATTENDANCE_QA_IMAGE" \
  -m unittest discover -s /qa/tests -p 'test_admin_direct_attendance.py' -v
```

همچنین `test_managers_manual_attendance.py` و `test_manager_excel_parser.py` باید PASS شوند. آزمون مرورگری در رزولوشن‌های موبایل و دسکتاپ، نمایش حالت تاریک/روشن، تست واقعی PostgreSQL روی شبکهٔ QA، تست شکست/تکرار/انقضای توکن، تست Session و Restore و Change Approval پیش از انتشار لازم است.
