# نسخهٔ آزمایشی 1.8.7 — صفحهٔ «اعمال تغییرات»

این بسته ادامهٔ سورس کامل نسخهٔ 1.8.6 است. صفحهٔ جدید **`GET /changes`** به منوی مدیر اضافه شده و امکانات موجود را در یک میزکار واحد گرد هم می‌آورد. **هیچ نصب، Migration یا تغییر دیتابیس Production انجام نشده است.**

## قابلیت‌های صفحه

1. جست‌وجوی کارکنان با نام و شمارهٔ دستگاه؛ انتخاب کارمند و تاریخ شمسی.
2. ویرایش نام و نام خانوادگی کارمند، شمارهٔ دستگاهِ بدون سابقهٔ تردد، و وضعیت فعال/معلق. شناسهٔ داخلی `employees.id` ثابت است. نام کاربری حساب ورود `users.username` در این صفحه قابل‌ویرایش نیست.
3. نمایش ثبت‌های خام آن روز و اولین/آخرین ساعت مؤثر؛ ثبت اصلاح ورود و خروج با دلیل و پیشگیری از ویرایش هم‌زمان با `expected_revision`.
4. لغو اصلاح فعال و نمایش حداکثر ۳۰ نسخهٔ آخر تغییرات روز، با نام مدیر و زمان.
5. ثبت دلیل تغییر مشخصات و وضعیت در `audit_logs` و محافظت سروری با نقش `admin`، CSRF و کنترل تغییر هم‌زمان اطلاعات کارمند.
6. بازگشت از فرم‌های تغییر به خود صفحهٔ `/changes`، بدون برهم‌زدن مسیرهای قدیمی `/employees` و `/corrections`.

## محدودیت‌های عمدی

- ثبت‌های خام دستگاه (`report_punches` و `attendance_logs`) و فایل DAT دست‌کاری نمی‌شوند.
- اگر شمارهٔ دستگاه دارای سوابقی در `attendance_logs`، `report_days`، `report_punches` یا `attendance_records` باشد، تغییر آن متوقف می‌شود؛ زیرا در Schema فعلی گزارش‌های تاریخی بر اساس `device_id` وصل می‌شوند. برای ویرایش امن این شناسه باید در مرحلهٔ بعد رابطه بر اساس `employee_id` ثابت و نگاشت شناسه‌های قدیمی اضافه شود.
- گزارش‌های فعلی هنوز از `report_sets/report_days/report_punches` به‌علاوهٔ `attendance_corrections` ساخته می‌شوند. **هنوز گزارش‌های کاملاً دیتابیس‌محور و روند رفع مغایرت قبل از Import پیاده نشده‌اند**. این بسته فقط صفحهٔ اعمال تغییرات روی قابلیت‌های موجود است.
- تغییر وضعیت کارمند به `deleted` فقط از مسیر جداگانهٔ تأیید حذف انجام می‌شود.
- این نسخه بدون Migration جدید طراحی شده است و همان Migration نسخهٔ 1.8.6 (`0002_corrections`) را نیاز دارد. هیچ Migration نباید روی Production بدون برنامهٔ جداگانه اجرا شود.

## آزمایش ایمن بدون Production

برای بررسی سریع ساختاری از Python میزبان، بدون اتصال به دیتابیس:

```bash
python3 -m compileall -q app/main.py tests/test_changes_workbench.py
python3 scripts/check_project.py .
```

تست‌های عملیِ جدید با دیتابیس موقتی SQLite **فقط با محیط تست جداگانه** و وابستگی‌های `app/requirements.txt` اجرا شوند:

```bash
PYTHONPATH=app python3 -m unittest -v tests/test_changes_workbench.py
```

برای سرور بدون Node روی میزبان، همان روش قبلی image موقت Docker برای فایل‌های `tests/*.cjs` کافی است. **تست SQL نباید به PostgreSQL در حال سرویس متصل شود**؛ فایل `test_changes_workbench.py` به‌اجبار URL را روی SQLite حافظه‌ای تنظیم می‌کند.

## معیار پذیرش نسخهٔ آزمایشی

- `viewer/operator/exporter` نتوانند صفحه یا مسیرهای ویرایش مدیر را فراخوانی کنند.
- تغییر نام، وضعیت و ساعت مؤثر با ثبت دلیل و تاریخچه ذخیره شود و بعد از آن گزارش روزانه نتیجهٔ اصلاحی را نشان دهد.
- نام کاربری حساب بدون تغییر بماند؛ تغییر شمارهٔ دارای سابقه رد شود.
- خام دستگاه و رکوردهای Import بدون تغییر باقی بمانند.
- درخواست فاقد CSRF یا با فرم قدیمی پس از ویرایش هم‌زمان رد شود.

**وضعیت انتشار:** سورس آزمایشی، هنوز برای Production تأیید نشده است. پیش از انتشار واقعی، تست‌های وابستگی، مرور UI در مرورگر، آزمایش روی PostgreSQL ایزوله، بکاپ/بازگردانی و کنترل rollback لازم است.
