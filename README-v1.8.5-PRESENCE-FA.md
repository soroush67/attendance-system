# گزارش مدت حضور ثبت‌شده — نسخه 1.8.5 (کاندیدا)

این نسخه بر اساس سورس کامل `v1.8.4.2` تهیه شده و **هنوز روی Production اعمال نشده است**.

## روش محاسبهٔ مورد تأیید

برای هر کارمند در هر روز **به وقت Asia/Tehran**، از همه ثبت‌های متمایز دستگاه، اولین و آخرین زمان استخراج و اختلاف آن‌ها محاسبه می‌شود. ثبت‌های تکراری با همان تاریخ/ساعت در چند گزارش نام‌گذاری‌شده، تنها یک بار در نظر گرفته می‌شوند. ثبت‌های چندثانیه‌ای متفاوت حذف نمی‌شوند؛ مثلاً چهار ثبت ۱۰:۴۹:۱۶، ۱۰:۴۹:۱۹، ۱۶:۴۸:۰۹، ۱۶:۴۸:۱۱ برابر با **۵ ساعت و ۵۸ دقیقه و ۵۵ ثانیه** اختلاف اولین تا آخرین ثبت است که پس از گردکردن **۰۵:۵۹** نمایش داده می‌شود، نه دو نوبت چندثانیه‌ای.

اگر در یک روز هیچ ثبت یا فقط یک زمان متمایز وجود داشته باشد، آن روز «ناقص» است؛ در حالت روزانه مدت آن «—» و در مجموع دوره، مدت نامشخصی برای آن حدس زده نمی‌شود. جمع مدت‌ها با دقت ثانیه انجام می‌شود و در پایان دوره به نزدیک‌ترین دقیقه گرد می‌شود. بنابراین در برخی مرزهای ثانیه‌ای، جمع اعداد گرد‌شدهٔ روزانه ممکن است یک دقیقه با مجموع دوره فرق کند.

**هشدار:** این گزارش *مدت حضور مشاهده‌شده بین دو ثبت* است و جایگزین محاسبه قانونی حقوق و دستمزد نمی‌شود. خروج‌های موقت، ناهار، شب‌کاری، مرخصی و اضافه‌کاری تأییدشده از دادهٔ خام بدون وضعیت معتبر IN/OUT قابل محاسبه نیستند.

## حالت‌های گزارش‌گیری

در «گزارش حضور»، ابتدا «از تاریخ شمسی» و «تا تاریخ شمسی» را انتخاب کنید. می‌توانید فقط یک کارمند (نام و شناسهٔ دستگاه) یا تمام افراد و یکی از گزارش‌های نام‌گذاری‌شده یا همهٔ آن‌ها را انتخاب کنید. سپس:

| حالت | نتیجه |
| --- | --- |
| روزانه | یک ردیف برای هر روز کارمند، اولین و آخرین ثبت، تعداد ثبت‌ها و مدت روز |
| ماهانه شمسی | یک ردیف در هر ماه شمسی واقع در بازهٔ انتخابی، تعداد روزهای ثبت‌شده و ناقص، مجموع حضور |
| سالانه شمسی | تجمیع مشابه بر مبنای سال شمسی |
| دورهٔ ماهانه شناور | دوره‌های مستقل با «روز شروع دوره» ۱ تا ۲۸؛ مثلاً ۲۰ ماه قبل تا ۱۹ ماه جاری |
| مجموع کل بازه | یک ردیف برای کارمند در کل فاصلهٔ شروع و پایان انتخاب‌شده |
| ثبت‌های خام | تمام ثبت‌های مشاهده‌شده با امکان بررسی خطا |
| جفت‌های متوالی | حالت تشخیصی قدیمی، **نه مبنای مجموع ساعت** |

در همهٔ حالت‌ها، مرز شروع و پایان *شامل* روز انتخاب‌شده است. اگر بازه فقط بخشی از ماه/سال/دوره را بپوشاند، فقط همان بخش در مجموع وارد می‌شود. دکمه «ریز روزانه همین بازه» فیلترهای کارمند، فایل و تاریخ را حفظ می‌کند.

Excel از همان تابع فیلترشدهٔ صفحه تهیه می‌شود. ستون متنی `HH:MM` برای خواندن و ستون عددی «دقیقه» برای مرتب‌سازی و محاسبهٔ بعدی وجود دارد. اطلاعات چند کارمند با نام یکسان، به کمک شناسهٔ دستگاه تفکیک می‌شوند.

## تغییرات فنی و ایمنی

- تغییر در `app/main.py`، آزمون‌های گزارش و این راهنما؛ **بدون تغییر schema، Migration، Compose، متغیرهای محیطی یا فایل‌های داده**.
- دادهٔ ذخیره‌شده یا فایل‌های DAT به‌صورت خودکار دوباره‌پردازش نمی‌شوند.
- مجوز مشاهده و دانلود Excel مانند نسخهٔ قبل است؛ دانلود برای `admin/operator/exporter` و خواندن برای نقش‌های مجاز گزارش.
- نمایش این حالت نیازمند ثبت شناسهٔ دستگاه کارمند در جدول کارکنان است. خطای آپلود برای شناسهٔ ناشناس (`441094831` در نمونهٔ قبلی) جداگانه باید با ثبت کارمند واقعی یا تصمیم برای قرنطینهٔ ناشناس حل شود؛ این بسته سیاست واردکردن داده را عوض نمی‌کند.

## آزمون‌ها و روند انتشار

ابتدا روی سورس محلی:

```bash
python3 -m py_compile app/main.py tests/test_presence_hours.py
python3 -m unittest discover -s tests -p 'test_presence_math_stdlib.py' -v
node tests/test_report_sort.cjs
node tests/test_presence_duration_sort.cjs
python3 scripts/check_project.py .
```

سپس با **Image کاندیدای تازه‌ساخته‌شده از همین سورس** و پایگاه دادهٔ تست/SQLite، تمام تست‌های Python را در محیط دارای dependencies مطابق `app/requirements.txt` اجرا کنید:

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

برای استقرار واقعی، از Pipeline تأییدشده GitLab/Jenkins با image دارای Digest و preflight + smoke + rollback استفاده کنید؛ بدون تأیید، هیچ `docker compose up` یا جایگزینی release pointer انجام ندهید. سرویس‌های PostgreSQL، RustFS، exporter، آپلودها، `.env` و سه Compose فعلی Production نباید تغییر کنند. هر دستور دستی Compose مربوط به web باید `compose.ci-release.yml` را **آخر** وارد کند تا ناخواسته Image قدیمی جایگزین نشود.

این آرشیو شامل گواهی خصوصی CA، رمزها، فایل `.env` و اطلاعات واقعی کارکنان نیست. قبل از انتشار باید تست یکپارچهٔ وابسته به PostgreSQL/SQLite، تست مرورگر RTL در موبایل و هر دو تم، تست RBAC، و smoke و rollback روی staging گذرانده شود.
