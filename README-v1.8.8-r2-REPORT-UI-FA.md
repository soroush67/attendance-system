# سامانهٔ حضور و غیاب — کاندیدای v1.8.8-r2 (فقط محیط آزمایش)

این ZIP کل سورس را دارد و ادامهٔ مستقیم `v1.8.8-r1` است. قابلیت Reconciliation و Migrationهای `0001` تا `0003` حفظ شده‌اند. هیچ استقرار یا Migration روی Production با آماده‌سازی این بسته انجام نشده است.

## تغییر متمرکز روی گزارش روزانه

- «اعمال تغییرات» و «اصلاح تردد» از سلول نام کارمند خارج شدند و در یک ستون مستقل «عملیات» قرار گرفتند؛ این ستون تنها برای `admin` ساخته می‌شود. برای نقش‌های دیگر، هم خود لینک‌ها و هم ستون اضافی وجود ندارند.
- عنوان «تعداد ثبت» در نمایش HTML و Excel به «تعداد ثبت دستگاه» تغییر کرد تا مشخص شود `0` به معنای **نبود رویداد ثبت‌شده از دستگاه** است، حتی اگر ساعت مؤثر آن روز با اصلاح مدیر مشخص شده باشد. نحوهٔ محاسبهٔ حضور، داده‌های خام و Excel تغییری نکرده‌اند.
- اسکریپت مرتب‌سازی حالا ستون «عملیات» را به‌درستی به‌عنوان ستون غیرقابل‌مرتب‌سازی نادیده می‌گیرد؛ ستون‌های داده همچنان صعودی/نزولی و چنداولویتی هستند.
- روی برچسب «اصلاح مدیر» توضیح کوتاهی قرار گرفت که تفاوت ساعت مؤثر و شمارش دستگاه را بیان می‌کند.

## آزمون‌ها

در محیط توسعه، `py_compile`، `scripts/check_project.py`، `node tests/test_report_sort.cjs` و `node tests/test_presence_duration_sort.cjs` بدون خطا اجرا شدند.

اجرای مستقیم `tests/test_report_actions_visual.py` در محیط اجرای فعلی به علت محدودیت Socket مرورگر Chromium با خطای `Operation not permitted` متوقف شد؛ **QA بصری PASS اعلام نشده است**. این اسکریپت یک فیکسچر مصنوعی CSS/DOM است و جایگزین بازدید از نرم‌افزار واقعی هم نیست.

برای آزمون واقعی، از بستهٔ جداگانهٔ `attendance-v188r2-staging-lab.zip` استفاده کنید. آن ابزار روی PostgreSQL 18 و شبکهٔ کاملاً جدا با شناسهٔ منحصربه‌فرد آزمایش می‌کند؛ نتیجهٔ PG18 ریشهٔ جدید باید از خروجی سرور مشخص شود. پس از PASS، برای مرور UI از `attendance-v188r2-browser-preview.zip` استفاده می‌شود. هر دو ابزار `source` را با SHA256 کنترل می‌کنند.

## مرزهای ایمنی

- این نسخه **NOT PRODUCTION-READY** است. Migration جدیدی نسبت به r1 ندارد، اما هیچ مجوزی برای اعمال migration قبلی روی Production نمی‌دهد.
- به `.env`، دادهٔ کارمند واقعی، Volumeهای PostgreSQL، RustFS، Backup، Jenkins/GitLab، Compose Production یا Image عملیاتی دست نزنید.
- پیش از اجرای Preview جدید، اگر Preview قدیمی r1 هنوز روشن است، فقط با `stop --state <مسیر چاپ‌شدهٔ خودش>` آن را متوقف کنید. هرگز از حذف گروهی Docker استفاده نکنید.
- بعد از Smoke و مرورگر، گیت‌های Backup/Restore، Test Concurrency، Accessibility، Load، Security و Rollback همچنان باید جداگانه تأیید شوند.
